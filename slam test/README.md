# RoboMaster EP — Grid SLAM Explorer (Class Work 8)

โปรแกรมให้ DJI RoboMaster EP สำรวจเขาวงกตแบบตารางที่ไม่รู้แผนที่มาก่อน สร้างแผนที่ด้วย ToF บน gimbal
ประมาณตำแหน่งตัวเอง บันทึกแผนที่ไว้ใช้ต่อ และสั่งให้เดินไปช่องไหนก็ได้ด้วยการคลิก

- ขนาดสนาม **2×2 ถึง 7×7** ช่อง (ค่าเริ่มต้น 4×5) ช่องละ **0.6 × 0.6 m** (แก้ได้)
- มี **โหมดจำลอง (Sim)** ใช้ทดสอบได้โดยไม่ต้องต่อหุ่น
- เมื่อสำรวจเสร็จ ระบบจะสร้างไฟล์ส่งงานให้อัตโนมัติ: Map, Log, Trajectory, Accuracy, Coverage และจุดเริ่ม/จุดจบ

---

## 1. ติดตั้ง

```bash
# robomaster SDK รองรับ Python 3.7–3.8 (แนะนำ 3.8 64-bit บน Windows)
pip install matplotlib robomaster
```
ถ้าจะใช้แค่โหมดจำลอง ติดตั้งแค่ `matplotlib` ก็พอ (ใช้ Python เวอร์ชันไหนก็ได้)

## 2. เปิดโปรแกรม

```bash
python run.py                 # เปิด GUI
python run.py --sim --headless --seed 3            # ทดสอบจำลองแบบไม่เปิดหน้าต่าง
python run.py --sim --headless --w 7 --h 7 --sx 3 --sy 3 --heading E
python run.py --eval output/run_xxx/map.json --gt my_gt.json   # คำนวณผลย้อนหลัง
```

## 3. ขั้นตอนวันทดสอบจริง (แนะนำ)

1. เปิดหุ่นเป็นโหมด **AP (Wi-Fi Direct)** แล้วต่อ Wi-Fi คอมเข้ากับหุ่น ต้องติด **ToF ไว้บน gimbal ให้หันไปทางเดียวกับกล้อง**
2. `python run.py` → ตั้งค่า กว้าง/สูง, ช่องที่วางหุ่น (เริ่ม x,y) และ **ทิศที่หน้าหุ่นหัน** เทียบกับแผนที่
   (x = คอลัมน์ นับจากซ้าย, y = แถว นับจากล่าง, N = ขึ้น) → เลือก **หุ่นจริง** → กด **Apply / เชื่อมต่อหุ่น**
3. **Calibrate ToF** (ทำครั้งเดียว): วางหุ่นกลางช่องที่มีกำแพงอย่างน้อย 1 ด้าน แล้วกด *Calibrate ToF*
   โปรแกรมจะตั้ง `WALL_EXPECT_MM` และ `WALL_THRESHOLD_MM` ให้เอง (ถ้าอยากให้ใช้ค่านี้ตลอด ให้นำไปใส่ใน `config.py`)
4. **ทดสอบการเดิน**: เลือกโหมด *ไปยังช่องที่คลิก* แล้วคลิกช่องข้างๆ ที่ไม่มีกำแพง
   - ถ้าสั่งไปขวาแต่หุ่นไปซ้าย ให้ตั้ง `STRAFE_SIGN = -1` ใน `config.py`
   - ถ้าการแก้มุมผิดทาง โปรแกรมจะสลับทิศให้เองอัตโนมัติ (ดูข้อความ `[yaw] ... flipped` ใน log)
5. วางหุ่นกลับจุดเริ่ม → กด **▶ เริ่มสำรวจ** → รอจนเสร็จ ระบบจะ export ไฟล์ให้อัตโนมัติ
6. **ใส่ Ground Truth** ของสนามอาจารย์: กด *ล้าง GT* → เลือกโหมด *วาด Ground Truth* → คลิกเส้นที่เป็นกำแพงจริง
   → กด **📊 ประเมินผล + Export** จะได้ Map Accuracy และภาพ comparison.png
7. **บันทึกแผนที่** (my_map.json) เก็บไว้ใช้ต่อ

### ใช้แผนที่เดิมเพื่อเดินไปจุดไหนก็ได้
**โหลดแผนที่** → วางหุ่นไว้ช่องไหนก็ได้ → เลือกโหมด *ตั้งตำแหน่งหุ่น* (เลือกทิศใน "หน้าหุ่นหันทิศ" ก่อน) แล้วคลิกช่องนั้น
→ เลือกโหมด *ไปยังช่องที่คลิก* แล้วคลิกเป้าหมาย หุ่นจะวางเส้นทางด้วย A* แล้วเดินไป
ระหว่างทางหุ่นจะสแกนทุกช่องเพื่อยืนยันตำแหน่ง ถ้าเจอกำแพงที่ไม่มีในแผนที่ จะอัปเดตแผนที่แล้ววางเส้นทางใหม่เอง
ถ้าไม่แน่ใจว่าหุ่นอยู่ไหน กด **ฉันอยู่ไหน?** โปรแกรมจะบอกว่าช่องไหนมีลายกำแพงตรงกับที่เห็น

## 4. ไฟล์ผลลัพธ์ (อยู่ใน `output/run_วันที่_เวลา/`)

| สิ่งที่ต้องส่ง | ไฟล์ |
|---|---|
| 1. Map | `map.png`, `map.json` (ใช้โหลดกลับ), `map_cells.csv`, `walls_data.csv` |
| 2. Log การสำรวจ | `exploration_log.csv` (ทุกก้าว: เวลา, ช่อง, ตำแหน่งประมาณ, odometry, yaw, ToF 4 ทิศ, กำแพงที่เห็น) |
| 3. Robot Trajectory | `trajectory.png`, `trajectory.csv` |
| 4. Accuracy / Coverage | `report.txt`, `metrics.json`, `comparison.png` |
| จุดเริ่ม / จุดจบ | อยู่ใน `report.txt` และมาร์กไว้บนภาพ (START / END) |

- **Map Accuracy** = จำนวนช่องที่ทายกำแพงถูกครบทั้ง 4 ด้าน / จำนวนช่องทั้งหมด × 100 (ช่องที่ยังเป็น UNKNOWN นับว่าผิด)
- **Coverage** = จำนวนช่องที่หุ่นเข้าไปแล้ว / จำนวนช่องทั้งหมด × 100
- รายงานยังให้ *Edge accuracy* (ความถูกต้องรายเส้นกำแพง) มาเป็นข้อมูลเสริมด้วย

## 5. หลักการ (ใช้ประกอบการนำเสนอ)

**Map representation:** แผนที่เป็นกริด เก็บสถานะของ *ขอบช่อง* แต่ละเส้น (กำแพงระหว่างช่อง) เป็นค่า **log-odds**
การวัดแต่ละครั้งจะบวก +1 ถ้าเจอกำแพง และ −1 ถ้าโล่ง (เป็น Bayesian occupancy update)
ถ้าค่ามากกว่า 0.5 ถือเป็นกำแพง น้อยกว่า −0.5 ถือว่าโล่ง ค่าระหว่างนั้นยังไม่รู้
เส้นหนึ่งจะถูกวัดจากทั้งสองช่องที่อยู่ติดกัน ค่าที่ได้จึงยืนยันกันเอง

**Sensing:** ตัวถังไม่หมุนเลย ใช้ gimbal หมุน ToF ไป 4 ทิศ อ่านทิศละ 7 ค่าแล้วเอา median
ถ้าค่าที่อ่านได้ใกล้ threshold หรือขัดกับแผนที่เดิม จะอ่านซ้ำแล้วโหวตเสียงข้างมาก

**Localization:**
1. *Grid dead-reckoning*: เดินทีละ 0.6 m ด้วย `chassis.move` ล้อ mecanum เดินข้างได้โดยไม่ต้องหมุนตัว จึงไม่สะสม error มุม
2. *IMU yaw correction*: หลังเดินทุกก้าว ใช้มุม yaw จาก IMU แก้ตัวถังให้กลับมาตรง
3. *Wall-based recentering*: ใช้ระยะถึงกำแพงจาก ToF คำนวณว่าหุ่นเบี่ยงจากกลางช่องเท่าไร แล้วขยับกลับ ทำให้ error ไม่สะสม
   ถ้าต้องแก้มากกว่า 6 cm จะวัดซ้ำก่อนขยับ
4. *Map matching*: ทุกครั้งที่กลับมาช่องเดิม จะเทียบลายกำแพงที่เห็นกับแผนที่
   ถ้าต่างกันตั้งแต่ 2 ด้านขึ้นไปจะเตือน (LOCALIZATION WARNING) และถ้ามีช่องข้างเคียงช่องเดียวที่ตรงกัน จะย้ายตำแหน่งไปช่องนั้น (relocalize)
5. *Collision check*: หลังเดิน ถ้า ToF ด้านหน้าใกล้ผิดปกติ แปลว่าเดินไม่สำเร็จ จะถอยตำแหน่งกลับช่องเดิม

**Exploration:** ใช้ **BFS หา frontier** คือช่องที่ยังไม่เคยไปที่ใกล้ที่สุดที่ไปถึงได้ แล้ววางเส้นทางด้วย **A\***
ก่อนเดินทุกก้าวจะยืนยันทิศนั้นด้วย ToF อีกครั้ง ถ้าไม่มี frontier เหลือแล้ว จะกลับไปวัดซ้ำเส้นที่ยังไม่แน่ใจ
และกำแพงที่กั้นช่องที่ยังไม่ได้ไป (กันกำแพงหลอกจาก noise) จนกว่าจะครบ

**Navigation:** A\* บนแผนที่ที่รู้ ถ้าระหว่างทางเจอกำแพงใหม่ จะอัปเดตแผนที่แล้ววางเส้นทางใหม่ทันที

## 6. ผลทดสอบในโหมดจำลอง
ตั้งค่า ToF noise σ = 12 mm, ค่าหลุด (outlier) 3%, error การเดิน σ = 3 cm ต่อก้าว

| สนาม | จำนวนแผนที่สุ่ม | Coverage | Map Accuracy |
|---|---|---|---|
| 4×5 | 30 | 100% ทุกแผนที่ | 100% ทุกแผนที่ |
| 7×7 | 25 | 100% ทุกแผนที่ | 100% ทุกแผนที่ |

ผลกับหุ่นจริงจะขึ้นกับการ calibrate และสภาพสนาม ควรทดสอบก่อนวันส่งงาน

## 7. ค่าที่ควรรู้ใน `config.py`
| ค่า | ความหมาย |
|---|---|
| `GRID_W, GRID_H, CELL_M` | ขนาดสนามเริ่มต้น (ใน GUI แก้ได้) |
| `WALL_EXPECT_MM` | ระยะที่ ToF อ่านได้เมื่อหุ่นอยู่กลางช่องและมีกำแพงติด (ได้จากการ Calibrate) |
| `WALL_THRESHOLD_MM` | อ่านได้น้อยกว่าค่านี้ถือว่ามีกำแพง |
| `MOVE_MODE` | `strafe` (แนะนำ) หรือ `rotate` |
| `STRAFE_SIGN`, `YAW_SIGN` | ใช้กลับทิศถ้าหุ่นเดินข้างหรือหมุนผิดทาง |
| `TOF_INDEX` | ToF ตัวที่ใช้ (0–3) ถ้าเสียบพอร์ตอื่น |
| `ASSUME_BOUNDARY_WALLS` | ถือว่าขอบนอกสนามเป็นกำแพง |
| `RETURN_HOME` | สำรวจเสร็จแล้วให้กลับจุดเริ่มหรือไม่ |

```

gui.py         หน้าจอ Tkinter: คลิกเลือกจุด, แก้แผนที่, วาด GT
explorer.py    SLAM loop: sense → map → localize → plan → act, go_to, relocalize
grid_map.py    แผนที่ log-odds ของขอบช่อง, BFS frontier, A*, save/load JSON
robots.py      RealRobot (robomaster SDK) และ SimRobot (จำลอง)
evaluation.py  Accuracy/Coverage, วาด map/trajectory/comparison, export
config.py      ค่าตั้งค่าทั้งหมด
```
